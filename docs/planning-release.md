## اطلاعات و پشتیبان

اطلاعات تکمیلی هر کار در همان کار و اطلاعات برنامه‌ریزی نسخه‌دار در تنظیمات موجود نگهداری می‌شوند. جداول و مسیر نصب قبلی جایگزین نشده‌اند. نوشتن تنظیمات برنامه‌ریزی با شمارهٔ بازبینی و مقایسهٔ اتمی محافظت می‌شود. در شروع خالی هیچ دادهٔ نمایشی خودکار ساخته نمی‌شود.

پشتیبان عادی و رمزگذاری‌شده شامل اطلاعات جدید هستند. بازیابی جایگزینی و بازگرداندن نسخهٔ پیش از بازیابی آزمایش شده‌اند. فایل نامعتبر پیش از تغییر اطلاعات رد می‌شود. هنگام خطای خروجی، فایل ناقص جایگزین تولید نمی‌شود. در بازیابی فایل قدیمی فاقد تنظیمات، برنامه‌ریزی قدیمی پاک و تنظیمات نامرتبط مانند تم حفظ می‌شوند.

ادغام پشتیبان دارای برنامه‌ریزی فعلاً پشتیبانی نمی‌شود؛ گزینه در رابط غیرفعال و در هر سه آداپتور رد می‌شود. برای این فایل‌ها از جایگزینی کامل همراه با نسخهٔ بازگشت استفاده می‌شود.

## اعتبارسنجی انجام‌شده

- بررسی TypeScript: `npm run lint` موفق.
- ساخت تولیدی: `npm run build` موفق؛ PWA شامل Worker و ۳۱ فایل کش‌شونده است.
- مجموعهٔ آزمون‌ها: ۹۹ موفق، صفر خطا و صفر آزمون ردشده؛ شامل آزمون‌های قبلی و آزمون‌های جدید موتور و حفظ داده.
- Chrome آزمایشی با نمایهٔ تازه: ساخت پروژه و مرحله، کار با پروژه/یادداشت، بازخوانی، رویداد، عدد اعشاری فارسی، قالب دسته‌ای، دسترسی به ابزار مخفی، پیش‌نمایش/اعمال ظرفیت و محتوای فایل پشتیبان موفق.
- هر پنج صفحهٔ جدید در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۳۶۶ با تم روشن و تاریک بررسی شدند؛ بیرون‌زدگی افقی صفحه مشاهده نشد.
- نسخهٔ تولیدی پس از قطع شبکه بازخوانی شد و محاسبهٔ ظرفیت با Worker از کش آفلاین اجرا شد؛ خطای زمان اجرای مرورگر ثبت نشد.

در محیط محدود این اجرا `os.userInfo` در Node خطا می‌دهد. آزمون‌ها با پیش‌بارگذار `test-userinfo.cjs` اجرا شدند که فقط در صورت خطای محیطی، اطلاعات کاربر آزمایشی برمی‌گرداند؛ کد محصول و منطق آزمون‌ها تغییر نکرده‌اند. دستور بازتولید در بستهٔ شواهد قرار دارد. در محیط عادی از `npm test` استفاده شود.

بازتولید در این محیط: `node --require ./scripts/test-userinfo.cjs --import tsx --test src/utils/*.test.ts src/infrastructure/web/dexieAdapter.test.ts src/infrastructure/bridge/bridgeAdapters.test.ts`. برای آزمون اختیاری مرورگر، Playwright را بدون تغییر package.json نصب کنید، نسخهٔ تولیدی را محلی سرو کنید و `scripts/qa-planning.cjs` را با متغیرهای `KAIROS_QA_URL` و `KAIROS_QA_OFFLINE=1` اجرا کنید. این آزمون از نمایهٔ تازه و دادهٔ آزمایشی استفاده می‌کند؛ خروجی در `qa-output` نوشته می‌شود.

## محدودیت‌های مشخص

- بستهٔ نصبی ویندوز ساخته و روی برنامهٔ نصب‌شده اعمال نشده است؛ Rust/Cargo و ابزار ساخت بومی این دستگاه در دسترس نبودند. کد SQLite ویندوز اصلاح شده، اما کامپایل و آزمون روی دستگاه لازم است.
- اندروید در مخزن فقط کد تحویل WebView/Bridge دارد؛ پروژهٔ کامل Android/APK در دسترس نبود. کد Java حفظ تنظیمات در بازیابی اصلاح شده، اما روی دستگاه کامپایل و اجرا نشده است.
- جست‌وجوی زمان‌بندی محدود به ترتیب پایه و حداکثر ۲۰ جابه‌جایی و افق حداکثر ۹۰ روز است؛ پیدا نشدن برنامه به معنی اثبات ناممکن‌بودن نیست. محاسبه در Worker با مهلت ۲۰ ثانیه انجام می‌شود.
- بازهٔ قفل‌شدهٔ ناقص برای کار تقسیم‌ناپذیر نیازمند اصلاح کاربر است؛ خودکار شکسته نمی‌شود. برای حذف مرحلهٔ دارای کار، ابتدا کارها باید از آن مرحله خارج شوند.
- زمان پایان پیشنهاد است و از مدت کار و ظرفیت ثبت‌شده محاسبه می‌شود؛ با دادهٔ کم تخمین دستی نمایش داده می‌شود. ارزیابی برتری آماری الگوریتم روی سابقهٔ واقعی کاربر هنوز انجام نشده است.
- اندازهٔ اطلاعات برنامه‌ریزی برای جلوگیری از فایل غیرعادی به ۲ مگابایت محدود شده است. مهاجرت به جداول مستقل برای دادهٔ بسیار بزرگ در این نسخه انجام نشده است.
- حساب آنلاین، سرور، همگام‌سازی، پیوست/OCR و اعلان هنگام بسته‌بودن برنامه اضافه نشده‌اند؛ این موارد خارج از محدودهٔ پرامپت‌های اصلی بودند.

## اجرای خروجی

بستهٔ وب جداگانه‌ای که همراه این نسخه تحویل داده شده، خروجی ساخته‌شده و یک سرور محلی بدون وابستگی جانبی دارد. فایل `Start-Kairos.cmd` متعلق به آن بسته است و در سورس مخزن قرار ندارد. در ویندوز دارای Node.js، اجرای آن فایل برنامه را در نشانی ثابت `http://127.0.0.1:4388` باز می‌کند؛ داده‌های این نشانی در مرورگر همان نشانی ذخیره می‌شوند. برای انتقال از نسخهٔ فعلی، از داخل همان نسخه پشتیبان بگیرید و در این نسخه بازیابی کنید. بازکردن مستقیم `index.html` با `file://` برای Worker و PWA مناسب نیست.

برای اجرای سورس همین مخزن: `npm ci`، سپس `npm run build` و `npm run preview` را اجرا کنید و نشانی نمایش‌داده‌شده در ترمینال را باز کنید. برای بررسی کد از `npm run lint` و `npm test` استفاده کنید. برای نصاب بومی، محیط ساخت Tauri لازم است و سپس `npm run desktop:build` اجرا می‌شود. شناسهٔ برنامه `com.kairos.workspace` حفظ شده است.
